# Native architecture and protocol identities

Static investigation of `/Applications/HeyMelody.app/Wrapper/HeyMelody.app/HeyMelody`, 2026-10-12. This map identifies shipped metadata, strings, imports, and model-independent command names. **It is not a recovered call graph or a validated earbud protocol.**

Type-field associations are decoded from Swift nominal/field metadata, not inferred from adjacent strings. Symbolic Swift type references and executable call relationships remain undecoded.

## Command families and framing clues

Swift reflection gives **case names, not numeric raw values or wire encodings**:

- `PollCommands` (`0x101593914`) includes battery/version/capability/MTU/protocol/earbud-state queries; `getNoiseReductionToggleV2`, EQ, custom EQ, multipoint, codec, hearing/ear-scan/personalization, tone, spatial audio, game effect, touch/head gestures, and `getGATTOverEdrState`. Preserve the shipped spellings such as `getRemoteCapablities`.
- `SetCommands` (`0x1015a0418`) includes `setFindMode`, gesture functions, feature switches, ANC, EQ/custom EQ, tone/Zen/personalization, hearing/ear-scan tests, `setAITranslateState`, `setHostCapabilities`, `setDualConnection`, touch/head gesture controls, and `restoreFactorySetting`.
- `NotificationCommands` (`0x10159e864`) includes register/cancel/query registration, capabilities, events, and register-all cases.
- `ReceiveCommands` (`0x10158ef00`) includes time, switch/EQ/custom-EQ/spatial-audio state, firmware-version change, tips, and neck-health cases.
- `OTAUpgradeCommands` (`0x10159fb58`) includes `sync`, `start`, `zoningStart`, `data`, `blockVerify`, `isValidationDone`, `commit`, `abort`, `transferCompleteIND`, and `errorIND`.

Decoder identities separately include battery, MTU, protocol/version, feature/status/capability, notifications, hearing, EQ, and OTA confirmation decoders. Reflection alone does not reveal numeric payload layouts. The full field/case inventory and exact reflected-name offsets are in A2.

Framing clues in A2 include `parseFrameData(data:for:)` (`0x1014cddc0`), `otaFrameRequest(command:for:timeout:onSuccess:onError:)` (`0x1014ce310`), `checksumMismatch`, and CRC type identities `Crc8`, `Crc16`, `Crc16Ccitt`, `Crc16CcittKermit`, `Crc16Dnp`, `Crc32`. The existence of multiple CRC algorithms does not establish which protects control frames or firmware.

Diagnostic strings explicitly mention notification command `0x8308` at `0x1014cdde0`, OTA command `0x0301` at `0x1014b5110`, OTA sync-confirm `0x0300` at `0x1014b51d0`, and a `0x0304` file-check failure at `0x1014dc180`. These are **candidate semantic clues from text**, not decoded executable constants or an implemented command table. Byte order, framing prefix, lengths, sequence/correlation ID, CRC coverage, notification format, and opcode mapping remain unknown.

## Service endpoints and feature dependencies

A2 contains regional `iot-earbuds-*` URLs and translation/voice WebSocket URL strings. Examples include `https://iot-earbuds-in.allawnos.com/` at file offset `21692416` and `wss://earbuds-translate-cn.wanyol.com/voicebox/ws/channel` at offset `21666896`. Only bytes were inspected; no endpoints were contacted.

Together with networking/WebSocket/opus dependency identities, these are evidence that a fully functional clone may require server-side behavior as well as Bluetooth. They do not prove current availability, API schema, authorization requirements, region selection, licensing, or OnePlus Buds 4 support. A2 also retains bare `http://`/`https://` strings, which are not service endpoints.
